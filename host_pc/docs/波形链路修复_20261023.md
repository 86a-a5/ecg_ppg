## 已修复的问题

| 问题 | 原来的影响 | 修复 |
|---|---|---|
| UART 出错后可能整批重发，上位机实际没有去重 | 旧时间戳和重复样本再次进入滤波、录制，序号统计也可能产生虚假丢帧 | 以完整帧判重，保留最近 512 帧，覆盖 4096 字节发送队列的重试；重复帧计数单独显示 |
| 下位机 PPG FIFO 溢出后仍上传旧队列，并按当前时刻倒推时间 | 旧波形被标成最新波形，破坏 ECG/PPG 时间对应关系 | 溢出时计数，停止转换、清 FIFO、恢复转换；不上传无法可靠定时的积压样本 |
| FIFO 恢复的 I²C 写入失败可能让传感器停在 shutdown | 后续无数据且缺少恢复路径 | 保留 restart_pending，下次轮询重试完整启动流程 |
| 显示允许最多三个周期间隔，漏一个点也不重置 | 缺失数据被连线，滤波继续使用跨间断的状态 | 超过 1.5 个周期即断线并重置；正常连续数据保持原滤波参数 |
| PPG 接触大阶跃重置后返回零，平滑仍跨越该点 | 接触变化被画成连续过渡 | 在显示数据插入 NaN 断点，SG 平滑不跨接触断点 |
| 缓冲按点数保存，旧尖峰可能已经移出横轴但仍参与缩放 | 当前可见波形被压扁 | 仅使用当前可见六秒窗口内的样本计算纵轴范围 |

FIFO 行为依据 [MAX30102 官方数据手册](https://www.analog.com/media/en/technical-documentation/data-sheets/max30102.pdf) 的 FIFO Overflow Counter：满 FIFO 会丢失新样本，计数器在 31 饱和。不能总用溢出计数精确恢复旧样本时间，所以采用丢弃不确定积压并重新开始的恢复策略。

去重只删除最近缓存内完全一致的传输帧，包含类型、序号、数值和时间戳；不会仅因序号回绕或数值相同就删除新的采样点。原始录制不使用显示滤波结果。

重新启动 `start_gui.bat` 即可使用上位机修复。固件产物位于同级 `stm32f4/ECG_PPG/build-link/ECG_PPG.elf`、`.bin`、`.hex`，本次已经重新生成，但尚未写入开发板。
