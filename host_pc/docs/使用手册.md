## 2. 串口协议（12 字节定长帧，小端）

与下位机 `BSP/Inc/ecg_ppg_stream.h`、以及原 `ble04_pc_gui.py` 完全一致。

| 字节 | 内容 | 说明 |
|------|------|------|
| `[0]` | `0xAA` | 帧头 |
| `[1]` | 帧类型 | `0x01`=ECG / `0x02`=PPG |
| `[2]` | 序号 | ECG 与 PPG 共用同一个 8 位递增计数器 |
| `[3..4]` | ECG：ADC 原始值 | uint16，0~4095，中点约 2048 |
| | PPG：RED | uint16，MAX30102 18bit 原始值 `>> 2` |
| `[5..6]` | ECG：`0xFF 0xFF` | 填充 |
| | PPG：IR | uint16，18bit 原始值 `>> 2` |
| `[7..10]` | 时间戳 | uint32，TIM5 @1MHz，单位 µs |
| `[11]` | `0x55` | 帧尾 |

- **采样率**：ECG 200 Hz（TIM2 TRGO），PPG 100 Hz（`SPO2_CONFIG=0x27`）
- **带宽**：200×12 + 100×12 = **3600 B/s**，115200 波特率（≈11520 B/s）余量充足
- **时间戳**：TIM5 为 32 位 1 MHz，**约 71.6 分钟回绕一次**。上位机的
  `ecg_ppg_protocol.FrameParser` 会做回绕展开（unwrap），把时间戳还原成
  单调递增的秒数 —— 这是相对原 `ble04_pc_gui.py` 的关键修正，原脚本在
  回绕点会算出错误的采样率/心率。

## 5. 安装与运行

### 5.1 采集数据

```bash
python run.py gui
# 等价于直接用解释器跑 serial_ecg_ppg_gui.py
```

1. 插好 USB-TTL，点「刷新端口列表」，选中对应 COM 口（如 `COM5`）
2. 波特率保持 `115200`，点「连接」
3. 贴好 ECG 电极、手指放稳 MAX30102，观察左侧**信号质量**面板：
   - ECG 峰峰值建议 > 300 mV（低于 60 mV 视为导联脱落）
   - PPG IR 直流应在满量程 1%~95% 之间，灌注指数 > 1%
4. 设置录制时长，点「开始录制」
5. 点「导出 CSV（模型可用）」

导出的 CSV 列结构：

```
ecg_sync_time_s, ecg_processed, ecg_raw,
ir_sync_time_s,  ir_processed,
red_sync_time_s, red_processed
```

> `ecg_processed` 单位是 mV（相对 AD8232 零点）；`ir_processed` /
> `red_processed` 是 MAX30102 的 18 位原始值。
> 两路时间戳使用共同的 TIM5 基准；PPG 时刻由 FIFO 快照估计，仍有轮询延迟，
> 不能仅凭共同计时器认定为精确同步采样。

### 5.2 没有硬件？先用合成数据跑通

```bash
# 静息 30s
python run.py synth -o records/synth_rest.csv --seconds 30 --hr 72 --pat-ms 240

# 运动升压 60s：心率 68→106 bpm，PAT 250→195 ms
python run.py synth -o records/synth_ramp.csv --seconds 60 --hr 68 --pat-ms 250 --hr-ramp

# 然后照常跑特征提取
python run.py extract records/synth_ramp.csv --window 10 --plot
```

### 5.3 提取特征

```bash
python run.py extract records/synth_rest.csv --plot
```

输出：
- `<同名>_beats.csv` —— 每行一个心搏（PAT / PTT / RR / HR / PIR / T 等）
- `<同名>_windows.csv` —— 每 5 秒聚合一次（对接血压回归）
- `<同名目录>/features_preview.png` —— 检测结果预览图（`--plot`）

### 5.4 血压估计

**方式 A：Poon-Zhang 参数化（需一次袖带标定）**

```bash
python run.py bp records/synth_ramp_beats.csv --sbp0 120 --dbp0 77 --gamma 0.017
```

该方式只需一次参考血压 + 对应 PAT 中位数，适合作为基线对照。
注意：本系统测的是体表 ECG 与 PPG，R 峰到收缩峰的间隔严格说是 **PAT**
（含心脏电-机械延迟 PEP），不是纯 PTT。单点标定只在该个体、该状态下有效。

> **标定段的选择非常关键**（实测踩过）：`--calib-ratio 25` 表示用前 25%
> 的心搏做标定。标定段的 PAT 中位数必须与「量袖带血压的那一刻」对应，
> 否则会引入几十 mmHg 的系统性偏置。用全段中位数标定运动数据，
> 会得到约 −17 mmHg 的恒定偏差（因为运动段把中位数拉低了）。

**方式 B：UniCardio 预训练模型（生成连续 BP 波形）**

```bash
python run.py unicardio records/synth_rest.csv \
    --model-dir "<项目工作目录>/software/UniCardio/UniCardio/UniCardio-main/base_model" \
    --max-segments 1
```

（记得用 4.3 节说的 UniCardio venv 解释器。）

脚本会：重采样到 125 Hz → 切 4 秒/500 点片段 → 鲁棒归一化到 [-1,1] →
按「PPG + BP占位 + ECG + 空占位」拼接成 `[1,1,2000]` 张量 →
调 `model(x, n_samples=1, model_flag="021", borrow_mode=1, ...)` →
反归一化 `BP = norm*50 + 100` → 提取 SBP/DBP/MAP。
若模型目录或依赖不满足，脚本会**明确报告缺什么**，并导出构造好的片段
供人工核对接口，不会静默失败。

## 6. 算法设计要点（为什么这样写）

`_anchored_search()`（PPG 特征点定位）是本项目最容易写错的地方，
这里记录三个必须遵守的约束，都是实测踩坑换来的：

1. **索引与时间不能混算。** `pat = cand_peak / fs - r0`（先转秒再相减），
   不能写 `(cand_peak - r0) / fs` —— 前者是「采样点」，后者是「秒」，
   混算会让 PAT 变成 0.5~2 秒的乱值，导致几乎所有心搏被生理范围过滤掉。

2. **搜索窗要用绝对时间，不要用 RR 比例。** 论文原文说「在 RR 的
   0.1~0.9 倍窗找 onset」，但这个窗**会包含本心搏的收缩峰**，argmin
   必然落到峰后的舒张期波谷。心率越高、RR 越短，错得越离谱。
   本实现改为：先在 `[R+50ms, R+min(600ms, 0.85·RR)]` 的**绝对时间窗**
   内找收缩峰（最高点），再从峰向前回搜 onset（最低点）。

3. **回搜 onset 不能越过 R 波。** 回搜长度要取
   `min(0.35s, PAT - PAT_MIN_S)`，否则短 RR 时会定位到上一个心搏，
   使 `ptt = onset - R < 0` 被判为无效（实测会丢掉 ~40% 心搏）。

另外，`detect_r_peaks()` 的**质量指标**衡量的是「逐拍抖动」
（`1 - MAD/中位数×2`），不是「相对全段中位数的偏差」。因为运动时
心率本来就会连续变化（RR 可变 50%），用全局中位数会**把生理变化
误判成噪声**、质量虚低。另有一个 `rr_smoothness`（相邻 RR 一阶差分
平滑度），它对连续心率变化不敏感，更适合判断有无漏检/多检。

## 7. 验证结果（2026-10-09，合成数据）

| 数据集 | 时长/心率 | R 峰 | 配对心搏 | 检出 PAT | PAT 真值 | 节律平滑度 |
|--------|-----------|------|----------|----------|----------|-----------|
| `synth_rest` | 30s / 72 bpm | 36 | **35/35** | 244.1 ± 6.5 ms | 240 ms | 98% |
| `synth_ramp` | 60s / 68→106 bpm | 83 | **82/82** | 228.0 ± 20.7 ms | 195→250 ms | 97% |

R 峰检测精度（对 `synth_ramp`，与生成器真值逐拍比对）：
**83/83 检出，平均误差 −0.2 ms，标准差 1.5 ms，最大 2.6 ms，零漏检。**

血压趋势验证（`synth_ramp`，真值由真值 PAT 经同一 Poon-Zhang 反推）：

| 对比项 | 相关系数 |
|--------|----------|
| 检出 PAT vs 真值 PAT | **r = 0.948** |
| 估计 SBP vs 真值 SBP | **r = 0.944** |
| 估计 DBP vs 真值 DBP | **r = 0.947** |

四段均值能正确跟随「静息→运动→恢复」：
PAT 250→203→238 ms 对应 SBP 104→141→113 mmHg。

> 绝对误差（MAE ≈ 18 mmHg）主要来自**标定参考点错配**，不是算法本身：
> 用全段 PAT 中位数标定时，运动段把中位数拉低，造成恒定偏置。
> 改用首段标定（`--calib-ratio 25`）后 ΔSBP 回到 +24 mmHg 的合理量级。
> 这说明：**一次标定只能在一个状态下有效**，与文献结论一致。

UniCardio 接入：模型成功加载（无缺失权重告警），输入构造通过，
推理输出为**有搏动形态的** BP 波形（500 点，57.6~137.6 mmHg，
std 21.3，非平线）。由于输入是合成信号（分布外），绝对值偏低且需
真实袖带标定后才可参考。

## 8. 与原始 BLE 上位机的关系

项目里原有的 `ble04_pc_gui.py` 是**蓝牙透传**版本（ATK-BLE04 / HM-10）。
`src/ecg_ppg/gui/serial_ecg_ppg_gui.py` 是**串口直连**版本，两者：

- **协议解析完全一致**（都是上面的 12 字节帧），所以下位机不用改协议；
- 传输层不同：串口版用 `pyserial`，蓝牙版用 `bleak`；
- 串口版额外修正了**时间戳回绕 bug**，并补齐了**模型可用 CSV 导出**与
  **实时信号质量评估**（原 BLE 版没有 CSV 保存能力）。

如果之后要切回蓝牙，只需把 `SerialWorker` 换成 BLE 读取线程，
后端的 `FrameParser` + `Recorder` 可以原样复用。

## 9. 常见问题

**Q：连上串口但一直没数据？**
依次检查：① TX/RX 是否交叉（下位机 PA2→模块 RX）；② 波特率是否 115200；
③ 下位机是否已烧录并复位；④ 共地。GUI 在 5 秒无数据后会给出针对性提示。

**Q：波形很抖/有工频干扰？**
AD8232 已内置 0.5–40 Hz 滤波 + 右腿驱动。若干扰仍明显，检查电极接触与
导线走向，避免导线成环。软件侧 `ecg_ppg_signal.bandpass()` 会再做一次
零相位带通。

**Q：PPG 一直是平线？**
看 GUI 的「PPG 直流」面板：DC 接近 0 说明手指没放好；DC > 95% 说明光强
饱和。MAX30102 的 LED 电流在 `MAX.c` 里由 `REG_LED1_PA/REG_LED2_PA`（当前 `0x24`）
设定，可按肤色/接触压力微调。

**Q：心率/PAT 明显不对？**
先看 `extract_features.py` 输出的 PAT 分布。正常成年人指尖 PPG 的
PAT 约 150–350 ms。若大量超出，多半是 R 峰或收缩峰误检 —— 用 `--plot`
生成预览图直接看特征点标得对不对。

**Q：丢帧率偏高？**
GUI 的「链路统计」会显示丢帧率。若 > 5%，先确认下位机确实用了
DMA 发送（`STREAM_Start()` 里会探测 `huart2.hdmatx`），而非阻塞发送。

**Q：双击 `serial_ecg_ppg_gui.py` 报 `ModuleNotFoundError: No module named 'serial'` / `'matplotlib'`？**
说明你双击时用的是**没装这些库的那个 Python**（本机可能是 3.12 或其它版本）。
正确做法是**别直接双击 .py**，改用下面任一：

1. **双击 `start_gui.bat`** —— 它认准带 tkinter 的 Python，缺库自动装。
2. **双击 `launch_gui.py`** —— 同上，而且出错时窗口不会闪退，能看清原因。
3. 手动装到系统 3.14：
   ```bash
   "%LOCALAPPDATA%\Programs\Python\Python314\python.exe" -m pip install pyserial numpy scipy matplotlib
   ```

**Q：双击 `.bat` 完全没反应 / 一闪而过？**
两个可能：
1. **换行符不是 CRLF**（最常见）。Unix 的 LF 换行会让 `cmd.exe` 解析失败。
   检查：文件的 `CR` 数量应该等于 `LF` 数量；本项目生成的是 23/23。若为 0/23，
   说明被存成了 LF，需重新生成。
2. 找不到可用的 Python。此时 bat 会打印错误并 `pause`。

**先跑这条命令，它能一次性告诉你环境到底哪儿不对**：
```bash
python launch_gui.py --doctor
```

**Q：报 `No module named 'tkinter'`？**
说明该解释器没带 Tcl/Tk（托管版 3.13 就是这种）。换用官方 Python，
或 `set ECG_PPG_GUI_PY=<你的解释器路径>` 后跑 `run.py gui`。

**Q：说不清环境到底哪儿不对？**
跑 `python launch_gui.py --doctor` 或 `python run.py doctor`，
会把解释器与 tkinter/serial/numpy/scipy/matplotlib 状态各打一遍，并给出修复命令。

## 11. 重要声明

本系统的血压估计结果**仅供参考与算法验证**，不能作为临床诊断依据。

- Poon-Zhang 单点标定法对佩戴位置、接触压力、PPG 波形质量和个体血管
  特性很敏感，结果应作为趋势对照；
- UniCardio 是公开预训练模型，未针对本硬件数据训练，绝对值必须用真实
  袖带血压校准；
- 论文的 AAMI 精度（ME ≤ 5 mmHg、STD ≤ 8 mmHg）是在其专用硬件、
  24 名志愿者、XGBoost 多特征模型上取得的，不能直接套用到本系统。
