# 正式工程 BLE 接入验证（2026-10-25）

验证对象：`stm32f4/ECG_PPG` 正式采集固件 + `host_pc` 正式 GUI。
设备：STM32F411CEU6、ATK-BLE04（AA:BB:CC:DD:EE:FF）、AD8232、MAX30102。
使用实际传感器采样，不是合成数据；本次验证针对通信与同步绘图，不代表生理信号质量或血压精度验证。

## 结果

正式固件编译成功，FLASH 22,264B，RAM 6,224B；已通过 ST-Link 实际烧录并 `Verified OK`。UART2 115200 / TX DMA，HSE 25MHz；运行中 SWD 读到 SystemCoreClock=25,000,000。

同步处理后的 60 秒 GUI 实采验证通过：

| 项目 | 结果 |
|---|---:|
| 录制 ECG | 12,013 点，200.00Hz |
| 录制 PPG | 6,022 组 RED+IR，100.260Hz |
| ECG 最大时间间隔 | 5.002ms |
| PPG 最大时间间隔 | 10.001ms |
| 测量期协议坏帧 / 序号丢帧 / 重复帧 | 0 / 0 / 0 |
| 界面丢点 / 传输异常 | 0 / 无 |
| BLE MTU | 247 |
| 图中 ECG / IR / RED 点数 | 1196 / 596 / 596 |
| 三图横轴 | 共同的 -6～0 秒窗口 |

采样数量与解析总帧数略有不同：GUI 先接收有效数据，再开始 60 秒录制，解析统计覆盖录制前已接收的样本。窗口平滑显示会保留边缘，图中点数也不等于全部采样数。

源码回归共 31 项：30 项通过，1 项真实模型权重测试按原有环境开关跳过。包括 BLE 设备筛选、拆帧/合帧、错误 GATT、无线断开、主动断开、连接取消、连接缓存同步，以及原有协议、录制、滤波、模型输入接口测试。下位机本地 FIFO 恢复测试通过。

另外通过实际 Windows 界面操作验证“断开 → 搜索 → 发现模块 → 连接 → 恢复三路波形”。日常启动入口 `start_gui.bat` 已验证可选择项目 `.venv` 并启动实时采集。侧栏支持滚动，缩小窗口后仍可查看全部链路统计。

## 连接初期缓存问题

首轮验证保留在 `outputs/ble_integration_20261025`：模块输出了断连期间缓存的旧数据，录制开头约 0.225 秒后出现 30.43 秒时间戳跳跃，验证判定失败。

已在 BLE 接收端增加首个通知后约一秒的同步阶段：解析并舍弃初始化数据，保留半帧拼接，完成后才进入正式绘图、录制与测量统计。复测同步阶段舍弃 5,368B，相关序号跳变 149 单独保留在 `startup_parser`；正式测量阶段没有该跳跃。原始失败记录和复测记录均保留，没有覆盖。

8 位序号及无 CRC 的帧格式有诊断边界，0 序号丢帧不能证明任何条件下绝对无丢包。PPG 时间戳仍是 FIFO 轮询估计，尚未做精确 PAT 时序标定。
